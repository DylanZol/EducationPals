## 20:13 — `feature` — complete-evals-course — Offline Evals and LLM-as-Judge course, compounding build-alongs, and reviewer output

**Type**
feature

**Ask**
Complete the EducationPals AI Engineer Intern take-home from the supplied
assignment email. The deliverable needs a 90-minute, AI-generated, text-only
course with two or three lessons, compounding interactive build-alongs, offline
replay, captured output, and an auditable generation setup.

**Plan**
The existing repository already selected Evals and LLM-as-Judge and implemented
an auditable staged generation scaffold, but it intentionally lacked the
submission artifacts a reviewer would grade. The core risk was a polished course
that could not actually run offline. The course therefore uses three dependency
ordered artifacts: a human-labeled JSONL fixture, schema-validated cached judge
judgments, then a grader joining them by stable ID. A cached replay was chosen
over a live API call so the reviewer can reach the capstone without credentials
or network access. The fixture stays deliberately small so every metric cell is
traceable by hand.

**Action**
Added a backwards course plan with breaking points and checkpoints; three
generated lessons with three focused sections each; incremental build
instructions; a fixture validator; a schema and coverage validator for cached
judge output; and an offline capstone that prints the confusion matrix,
precision, recall, and error IDs. Captured expected CLI outputs and a generation
manifest, completed the required writeup answers, updated the README's offline
reviewer path, and taught the setup verifier to accept the committed generation
manifest as an auditable offline source when raw paid-provider caches are not
included.

**Result**
- Verification: Python 3.12 ran the three learner build commands end to end,
  producing the recorded fixture, judgment, and capstone output. All six
  repository unit tests passed; `python -m agent verify` reported PASS; and
  `scripts/package_submission.py zol-dylan` created a 45.7 KiB archive.
- Outcome: the submission now contains a complete learner path from fixture to
  calibrated grader without a paid API call.

## 20:30 — `feature` — harden-course-replay — Replayable AI generation evidence, 90-minute pacing, incremental builds, and captured output

**Type**
feature

**Ask**
Refine the completed EducationPals take-home so it credibly satisfies the
course's 90-minute duration, presents genuinely incremental build-alongs, and
proves that the submitted lessons and artifacts are reproducible from the
included AI-generation orchestration rather than being separate static files.

**Plan**
The original artifact chain reached the right capstone, but its short reading
time and pre-completed scripts made the build experience too thin. More
importantly, the agent's offline mode required unavailable cached responses,
while verification accepted a special submitted-artifact exception. That was
the wrong trade-off for an assignment that explicitly prioritizes generation
process evidence. The refinement makes validated cache replay authoritative,
uses four three-minute sections plus an 18-minute incremental build per lesson,
captures actual stdout, and keeps the small fixture honestly framed as a
diagnostic example rather than a production estimate.

**Action**
Added eight complete, schema-valid response envelopes for diagnostic, planning,
lesson, and review stages. Offline generation now validates cache metadata,
prompt hashes, normalized-output hashes, schemas, and secret-free envelopes
before rendering the committed files and recording exact provider metadata plus
asset hashes in the manifest. Expanded every lesson to four timed sections and
added an inline SVG of the artifact path. Reworked each build-along into four
commands that create, validate, materialize, and consume its artifact. Added a
replay runner that writes actual `output/lesson-0N-run.txt` transcripts and
compares them to expected output. Documentation now gives the complete
Python-3.12 offline reviewer path.

**Result**
- Verification: `python -m agent generate --offline`, the full learner replay,
  all nine Python 3.12 unit tests, `python -m agent verify`, section word-count
  checks, and `git diff --check` passed. All 12 prose sections are 300-500
  words, and the final replay reports TP=3, FP=1, FN=1, TN=3, precision 0.750,
  and recall 0.750.
- Outcome: reviewers can regenerate the course from the audited cache, follow
  incremental commands to the capstone, and compare their actual offline output
  with the committed transcripts.

## 20:50 — `defect` — exclude-visual-studio-index — Submission packager skipping locked Visual Studio workspace files

**Type**
defect

**Ask**
The final archive command failed with `PermissionError` while trying to read a
locked `.vs/.../FileContentIndex/*.vsidx` file created by Visual Studio.

**Plan**
The packager already excludes Git metadata, Python environments, test caches,
and prior archives, but not Visual Studio's workspace-local index. That
directory is both irrelevant to the submission and likely to contain locked
files whenever the solution is open. Excluding the whole `.vs` directory fixes
the root cause without weakening archive coverage.

**Action**
Added `.vs` to the packager's excluded directory parts.

**Result**
- Verification: `python scripts/package_submission.py zol-dylan` completed and
  produced an 84.5 KiB archive; a ZIP inspection confirmed it contains no
  `.vs` files.
- Outcome: Visual Studio's locked index files are no longer archive candidates.

**Files**

| File | Change |
|------|--------|
| `scripts/package_submission.py` | Excludes Visual Studio's `.vs` workspace directory. |
| `changelog/2026-09-14.md` | Records the packaging defect and resolution. |

**Follow-ups**
- None.
